# ビルド方法の要件定義

## 1. 全体構造の説明

本プロジェクトのビルドシステムは、Windowsローカル環境でGo言語（1.22以上）を使用してアプリケーションをビルド・テストするための統一された実行手段を提供する。プロジェクトルートに配置されたビルドスクリプトを通じて、コードのコンパイル、テスト実行、成果物の配置を一元管理する。

ビルドシステムは以下の要素で構成される：

- **メインのビルドスクリプト:** プロジェクトルートに配置され、すべてのビルド操作のエントリーポイントとなる
- **テスト実行機構:** ユニットテストと結合テストを分離して実行できる仕組み
- **成果物配置機構:** コンパイルされたバイナリを所定のフォルダに配置する仕組み
- **エラーハンドリング機構:** 各処理の成否を判断し、適切に終了コードを返す仕組み

## 2. 各ファイルの役割と機能

### 2.1 メインビルドスクリプト（プロジェクトルート）

- `build.bat`（バッチファイル、代替案）

**役割:**
- ビルド、テスト、検証のすべての操作の統一エントリーポイントとして機能する
- 実行モードの切り替えを可能にする（全テスト実行、ユニットテストのみ、結合テストのみ、ビルドのみなど）
- 各処理ステップの実行順序を制御する
- エラー発生時に適切な終了コードを返す

**主要な機能:**
1. **コードのコンパイル:** `go build` を実行してアプリケーションをビルドする（`go build` は自動的に依存関係を解決・ダウンロードする）
2. **バイナリの配置:** コンパイルされた実行可能ファイルを `bin/` フォルダに配置する
3. **ユニットテストの実行:** `_Unit` サフィックスを持つテスト関数のみをフィルタリングして実行する
4. **結合テストの実行:** `_Integration` サフィックスを持つテスト関数のみをフィルタリングして実行する
5. **全テストの実行:** ユニットテストと結合テストの両方を順次実行する

### 2.2 成果物フォルダ（bin/）

**役割:**
- ビルドによって生成された実行可能ファイルを格納する
- 既存の `bin/` フォルダを使用する

**機能:**
- ビルド前に既存のバイナリをクリーンアップするか、上書きする
- バイナリファイル名は、プロジェクト名または明確に識別できる名前を使用する

### 2.3 テスト実行機構

**ユニットテストの識別:**
- テスト関数名に `_Unit` サフィックスが含まれるものをユニットテストとして識別する
- Goの標準テストツール（`go test`）を使用し、テスト名パターンマッチングでフィルタリングする

**結合テストの識別:**
- テスト関数名に `_Integration` サフィックスが含まれるものを結合テストとして識別する
- `tests/integration/` フォルダ内のテストファイル、またはテスト名パターンマッチングでフィルタリングする
- 結合テストは、コンパイル済みのバイナリと設定ファイルが必要なテストとして実行する

**テスト実行の分離:**
- ビルドスクリプトは実行モードの引数または環境変数を受け取り、以下を選択できるようにする：
  - `all`: ユニットテストと結合テストの両方を実行（デフォルト）
  - `unit`: ユニットテストのみ実行
  - `integration`: 結合テストのみ実行
  - `build-only`: ビルドのみ実行、テストは実行しない

## 3. 実装の論理的な順序

### 3.1 ビルドスクリプトの実装順序

1. **基本的なスクリプト構造の作成**
   - プロジェクトルートにメインビルドスクリプトを配置する
   - スクリプトのエントリーポイントと基本的なエラーハンドリングを実装する

2. **ビルド機能の実装**
   - `go build` を実行してアプリケーションをコンパイルする機能を追加する
   - バイナリを `bin/` フォルダに配置する処理を実装する
   - Windows環境に適した実行可能ファイル名を指定する（例: `.exe` 拡張子）

3. **テスト実行機能の実装（ユニットテスト）**
   - `_Unit` サフィックスを持つテストをフィルタリングして実行する機能を実装する
   - `go test` コマンドに適切なパターンマッチングを適用する
   - テスト結果をログに出力し、失敗時にエラーを返す処理を実装する

4. **テスト実行機能の実装（結合テスト）**
   - `_Integration` サフィックスを持つテストをフィルタリングして実行する機能を実装する
   - `tests/integration/` フォルダ内のテストを対象とする処理を追加する
   - 結合テスト実行前にバイナリが存在することを確認する処理を実装する

5. **実行モード切り替え機能の実装**
   - コマンドライン引数または環境変数で実行モードを指定できる機能を追加する
   - 各モードに応じた処理フローを実装する

6. **エラーハンドリングとログ出力の強化**
   - 各処理ステップでのエラーを適切にキャッチし、ログに出力する機能を追加する
   - 終了コードを適切に設定する処理を実装する（成功: 0、失敗: 非0）

### 3.2 テスト駆動開発（TDD）に基づく実装順序

1. **ビルドスクリプト自体のテスト計画**
   - ビルドスクリプトの各機能が正しく動作することを確認するためのテスト計画を策定する
   - 実際のGoコードが存在しない状態でも、ビルドスクリプトの基本動作を確認できるテストを検討する

2. **段階的な機能追加と検証**
   - 各機能を追加するたびに、実際にスクリプトを実行して動作確認を行う
   - エラーケースも含めて、すべての実行モードで正しく動作することを確認する

## 4. テストの概要と計画

### 4.1 ビルドスクリプトのテスト観点

#### 4.1.1 ビルド機能のテスト
- **正常系:** 
  - 有効なGoコードが存在する場合、ビルドが正常に完了することを確認する
  - 生成されたバイナリが `bin/` フォルダに正しく配置されることを確認する
- **異常系:** 
  - コンパイルエラーがある場合に、適切なエラーメッセージを出力して終了コードを返すことを確認する
  - `bin/` フォルダが存在しない場合、自動作成されることを確認する

#### 4.1.2 ユニットテスト実行機能のテスト
- **正常系:** 
  - `_Unit` サフィックスを持つテストのみが実行されることを確認する
  - すべてのユニットテストが通過する場合、適切な終了コードを返すことを確認する
- **異常系:** 
  - ユニットテストが失敗した場合、エラーを報告して終了コードを返すことを確認する
  - テストが存在しない場合の動作を確認する

#### 4.1.3 結合テスト実行機能のテスト
- **正常系:** 
  - `_Integration` サフィックスを持つテストのみが実行されることを確認する
  - 結合テストがバイナリを使用する場合、事前にビルドが完了していることを確認する
  - すべての結合テストが通過する場合、適切な終了コードを返すことを確認する
- **異常系:** 
  - 結合テストが失敗した場合、エラーを報告して終了コードを返すことを確認する
  - 必要な設定ファイルが存在しない場合の動作を確認する

#### 4.1.4 実行モード切り替え機能のテスト
- **正常系:** 
  - 各実行モード（`all`, `unit`, `integration`, `build-only`）が正しく動作することを確認する
  - デフォルトモードが `all` であることを確認する
- **異常系:** 
  - 不正な実行モードが指定された場合、エラーメッセージを出力することを確認する

### 4.2 アプリケーションコードのビルド・テスト検証計画

ビルドスクリプトの実装が完了した後、実際のアプリケーションコードに対して以下を検証する：

#### 4.2.1 ビルド検証
- Go 1.22以上のバージョンでビルドが正常に完了することを確認する
- Gin、GORM、SQLiteの依存関係が正しく解決されることを確認する
- Windows環境で実行可能なバイナリが生成されることを確認する

#### 4.2.2 テスト実行検証
- ユニットテストが設定ファイルなしで実行できることを確認する
- 結合テストが設定ファイルとバイナリを使用して実行できることを確認する
- テスト関数の命名規則（`_Unit`, `_Integration`）が正しく機能することを確認する

## 5. 技術的な考慮事項

### 5.1 Windows環境での実装
  
- **バッチファイル（代替案）:** 
  - `build.bat` として実装する場合、Windows標準のコマンドプロンプトで実行可能
  - ただし、高度な文字列操作やエラーハンドリングがPowerShellと比べて制限される

### 5.2 Goテストのフィルタリング方法

- **パターンマッチング:** `go test -run` オプションを使用して、テスト関数名のパターンマッチングを実行する
  - ユニットテスト: `go test -run "_Unit$" ./...`
  - 結合テスト: `go test -run "_Integration$" ./... -tags=integration`（必要に応じて）
  
- **ディレクトリ指定:** `tests/integration/` フォルダ内のテストのみを実行する場合、`go test ./tests/integration/...` を使用する

### 5.3 バイナリファイル名の決定

- プロジェクト名に基づいた明確なファイル名を使用する（例: `game-list.exe`）
- ビルドスクリプト内で、プロジェクト名を環境変数または設定から取得できるようにする
- バイナリファイル名は、後続の結合テストで参照できるようにする

### 5.4 エラーハンドリングとログ出力

- 各処理ステップでエラーが発生した場合、明確なエラーメッセージを標準エラー出力に出力する
- 成功時も適切なログメッセージを出力し、処理の進行状況を可視化する
- 終了コードを適切に設定し、CI/CDパイプラインなどでビルドの成否を判断できるようにする

## 6. 実装完了の定義

ビルドスクリプトの実装は、以下の条件を満たした時点で完了とする：

1. **基本機能の動作確認:** ビルド、バイナリ配置が正常に動作することを確認する
2. **テスト実行機能の動作確認:** ユニットテストと結合テストを個別に実行できることを確認する
3. **実行モード切り替えの動作確認:** すべての実行モードが正しく機能することを確認する
4. **エラーハンドリングの確認:** 異常系のケースでも適切にエラーを報告することを確認する
5. **実際のアプリケーションコードでの検証:** 実際のGoコードが存在する状態で、全体的なビルドフローが正常に動作することを確認する

## 7. 今後の拡張性

ビルドスクリプトは、将来的に以下の機能を追加できるように設計する：

- **リント・フォーマットチェック:** `gofmt`, `golint` などのコード品質チェックツールの統合
- **コードカバレッジレポート:** テストカバレッジの計測とレポート生成
- **クリーン機能:** 生成されたバイナリや一時ファイルを削除する機能
- **環境変数の設定:** ビルド時の環境変数を設定する機能
- **並列テスト実行:** テストの並列実行による実行時間の短縮
