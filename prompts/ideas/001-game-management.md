# ゲームソフト管理サービス要件定義

## 1. サービスの目的と範囲

### 1.1 目的
保有しているゲームソフトの情報を一元管理するためのローカルデモアプリケーションを提供する。ユーザーは自身が所有するゲームソフトの情報を登録、検索、更新、削除することができ、保有ゲームの統計情報を確認できる。

### 1.2 適用範囲
- ローカル環境でのみ動作するデモアプリケーション
- 単一ユーザーでの利用を想定（認証・認可機能は不要）
- Web API形式で機能を提供
- データはSQLiteデータベースに永続化

### 1.3 対象外
- 複数ユーザーでの利用（マルチテナント機能）
- クラウド環境へのデプロイ
- 外部APIとの連携
- 画像やファイルのアップロード機能
- 認証・認可機能

## 2. 機能要件

### 2.1 ゲーム情報の登録機能

#### 2.1.1 概要
ユーザーが保有するゲームソフトの情報をデータベースに登録する。

#### 2.1.2 必須項目
以下の項目は登録時に必須とする：
- **タイトル**: ゲームソフトの名称（文字列、最大255文字）
- **発売年**: ゲームの発売年（整数、4桁の年、例: 2024）
- **発売会社**: ゲームを発売した会社名（文字列、最大255文字）
- **プラットフォーム**: ゲームが動作するプラットフォーム（文字列、最大100文字、例: "PlayStation 5", "Nintendo Switch", "PC", "Xbox Series X"）

#### 2.1.3 任意項目
以下の項目は登録時に任意とする：
- **シリーズ**: ゲームが属するシリーズ名（文字列、最大255文字、例: "ファイナルファンタジー", "モンスターハンター"）
- **ジャンル**: ゲームのジャンル（文字列、最大100文字、例: "アクション", "RPG", "アドベンチャー", "シミュレーション"）
- **価格**: 購入時の価格（整数、単位: 円、0以上の値）

#### 2.1.4 システム項目
以下の項目はシステムが自動的に設定する：
- **ID**: 主キー（自動採番、uint型）
- **CreatedAt**: 登録日時（自動設定、time.Time型）
- **UpdatedAt**: 更新日時（自動更新、time.Time型）

#### 2.1.5 動作要件
- 必須項目がすべて入力されている場合のみ登録を許可する
- 必須項目が不足している場合は、エラーメッセージを返す
- 登録成功時は、登録されたゲーム情報をレスポンスとして返す
- 同一タイトル・同一プラットフォームの重複登録は許可する（制限しない）

### 2.2 ゲーム情報の一覧取得機能

#### 2.2.1 概要
登録されている全ゲームの一覧を取得する。

#### 2.2.2 基本動作
- 登録されている全ゲームの情報を配列形式で返す
- ゲームが0件の場合は空配列を返す
- デフォルトでは登録日時の降順（新しい順）でソートする

#### 2.2.3 ソート機能
以下の項目でソート可能とする：
- タイトル（昇順・降順）
- 発売年（昇順・降順）
- 登録日時（昇順・降順、デフォルト）

#### 2.2.4 フィルタリング機能
以下の条件でフィルタリング可能とする：
- **プラットフォーム**: 指定したプラットフォームのゲームのみ取得
- **発売会社**: 指定した発売会社のゲームのみ取得
- **ジャンル**: 指定したジャンルのゲームのみ取得（ジャンルが登録されているゲームのみ）
- **シリーズ**: 指定したシリーズのゲームのみ取得（シリーズが登録されているゲームのみ）
- **発売年範囲**: 最小発売年と最大発売年を指定して範囲でフィルタリング
- **複数条件の組み合わせ**: 上記の条件を複数組み合わせてフィルタリング可能

#### 2.2.5 動作要件
- フィルタリング条件が指定されていない場合は全件取得
- フィルタリング結果が0件の場合は空配列を返す
- ソート条件が指定されていない場合はデフォルトソートを適用

### 2.3 ゲーム情報の更新機能

#### 2.3.1 概要
既存のゲーム情報を更新する。

#### 2.3.2 更新方式
- 部分更新をサポートする（リクエストで指定されたフィールドのみ更新）
- 必須項目（タイトル、発売年、発売会社、プラットフォーム）も更新可能
- 任意項目はnullまたは空文字列を指定することで未設定に戻すことができる

#### 2.3.3 動作要件
- 存在するゲームIDを指定した場合、指定されたフィールドのみ更新する
- 存在しないゲームIDを指定した場合、404エラーを返す
- 必須項目を空に更新しようとした場合、400エラーを返す
- 更新成功時は、更新後のゲーム情報をレスポンスとして返す
- UpdatedAtは自動的に更新される

### 2.4 ゲーム情報の削除機能

#### 2.4.1 概要
ゲームIDを指定して、該当するゲーム情報をデータベースから削除する。

#### 2.4.2 削除方式
- 物理削除を採用する（論理削除は実装しない）
- 削除後はデータベースから完全に削除される

#### 2.4.3 動作要件
- 存在するゲームIDを指定した場合、該当ゲームを削除する
- 存在しないゲームIDを指定した場合、404エラーを返す
- 削除成功時は204 No Contentを返す

### 2.5 ゲーム情報の検索機能

#### 2.5.1 概要
タイトルによる部分一致検索を提供する。

#### 2.5.2 検索対象
- タイトルフィールドに対して部分一致検索を実行する
- 大文字・小文字は区別しない（case-insensitive）

#### 2.5.3 動作要件
- 検索キーワードが指定された場合、タイトルにキーワードが含まれるゲームをすべて返す
- 検索キーワードが空の場合は全件を返す
- 検索結果が0件の場合は空配列を返す

### 2.6 統計情報取得機能（オプション）

#### 2.6.1 概要
登録されているゲームの統計情報を集計して返す。

#### 2.6.2 統計項目
以下の統計情報を提供する：
- **登録ゲーム総数**: データベースに登録されているゲームの総数
- **プラットフォーム別のゲーム数**: 各プラットフォームごとのゲーム数を集計
- **発売会社別のゲーム数**: 各発売会社ごとのゲーム数を集計
- **ジャンル別のゲーム数**: 各ジャンルごとのゲーム数（ジャンルが登録されているゲームのみ集計）
- **シリーズ別のゲーム数**: 各シリーズごとのゲーム数（シリーズが登録されているゲームのみ集計）
- **総購入金額**: 価格が登録されているゲームの価格の合計
- **平均価格**: 価格が登録されているゲームの価格の平均値

#### 2.6.3 動作要件
- 統計情報はリアルタイムで集計する（キャッシュは使用しない）
- 価格が登録されていないゲームは価格関連の統計から除外する
- ジャンルやシリーズが登録されていないゲームは該当する統計から除外する

## 3. 非機能要件

### 3.1 パフォーマンス要件
- ゲーム一覧取得（100件程度）は1秒以内にレスポンスを返す
- ゲーム登録・更新・削除は1秒以内に処理を完了する
- 統計情報取得は2秒以内にレスポンスを返す

### 3.2 可用性要件
- ローカル環境でのみ動作するため、可用性の要件は特に定めない

### 3.3 セキュリティ要件
- 認証・認可機能は不要（単一ユーザー利用を想定）
- SQLインジェクション対策はGORMの機能を利用する
- 入力値のバリデーションを実装する

### 3.4 ログ要件
- すべてのHTTPリクエストとレスポンスをログに記録する
- エラー発生時は詳細なエラーログを出力する
- ログにはリクエストの詳細（メソッド、パス、パラメータ）を含める

### 3.5 エラーハンドリング要件
- 適切なHTTPステータスコードを返す（200, 201, 204, 400, 404, 500）
- エラーレスポンスは統一されたJSON形式で返す
- エラーメッセージはユーザーに分かりやすい内容とする

## 4. データ要件

### 4.1 データベース属性

#### 4.1.1 必須項目
- **タイトル** (Title)
  - 型: 文字列 (string)
  - 最大長: 255文字
  - 制約: 必須、空文字列不可

- **発売年** (ReleaseYear)
  - 型: 整数 (int)
  - 制約: 必須、4桁の年（例: 1900-9999の範囲）

- **発売会社** (Publisher)
  - 型: 文字列 (string)
  - 最大長: 255文字
  - 制約: 必須、空文字列不可

- **プラットフォーム** (Platform)
  - 型: 文字列 (string)
  - 最大長: 100文字
  - 制約: 必須、空文字列不可

#### 4.1.2 任意項目
- **シリーズ** (Series)
  - 型: 文字列 (string)
  - 最大長: 255文字
  - 制約: 任意、null許容

- **ジャンル** (Genre)
  - 型: 文字列 (string)
  - 最大長: 100文字
  - 制約: 任意、null許容

- **価格** (Price)
  - 型: 整数 (int)
  - 制約: 任意、0以上の値、0は未登録を表す

#### 4.1.3 システム項目
- **ID** (ID)
  - 型: 符号なし整数 (uint)
  - 制約: 主キー、自動採番

- **作成日時** (CreatedAt)
  - 型: 日時 (time.Time)
  - 制約: 自動設定、更新不可

- **更新日時** (UpdatedAt)
  - 型: 日時 (time.Time)
  - 制約: 自動更新

### 4.2 データ整合性要件
- 主キー（ID）は一意であること
- 必須項目は常に値が設定されていること
- 発売年は妥当な範囲内であること（1900-9999）
- 価格は0以上の値であること

### 4.3 データ永続化要件
- データはSQLiteデータベースに永続化する
- データベースファイルはプロジェクトルートに配置する（`game-list.db`）
- データベース接続はGORMを使用して管理する

## 5. API要件

### 5.1 API形式
- RESTful API形式で提供する
- リクエスト・レスポンスはJSON形式を使用する
- HTTPメソッドは適切に使用する（GET, POST, PUT, DELETE）

### 5.2 エンドポイント要件

#### 5.2.1 ゲーム登録
- **メソッド**: POST
- **パス**: `/games`
- **リクエストボディ**: ゲーム情報のJSON（ID、CreatedAt、UpdatedAtは除外）
- **レスポンス**: 201 Created + 作成されたゲームオブジェクト
- **エラー**: 400 Bad Request（バリデーションエラー）、500 Internal Server Error

#### 5.2.2 ゲーム一覧取得
- **メソッド**: GET
- **パス**: `/games`
- **クエリパラメータ**: 
  - `platform`: プラットフォームでフィルタ（オプション）
  - `publisher`: 発売会社でフィルタ（オプション）
  - `genre`: ジャンルでフィルタ（オプション）
  - `series`: シリーズでフィルタ（オプション）
  - `min_year`: 最小発売年（オプション）
  - `max_year`: 最大発売年（オプション）
  - `sort`: ソート項目（title, release_year, created_at、デフォルト: created_at）
  - `order`: ソート順（asc, desc、デフォルト: desc）
- **レスポンス**: 200 OK + ゲーム配列
- **エラー**: 500 Internal Server Error

#### 5.2.3 ゲーム更新
- **メソッド**: PUT
- **パス**: `/games/:id`
- **パスパラメータ**: `id` (uint)
- **リクエストボディ**: 更新するフィールドのみを含むJSON（部分更新対応）
- **レスポンス**: 200 OK + 更新されたゲームオブジェクト
- **エラー**: 400 Bad Request（バリデーションエラー）、404 Not Found、500 Internal Server Error

#### 5.2.4 ゲーム削除
- **メソッド**: DELETE
- **パス**: `/games/:id`
- **パスパラメータ**: `id` (uint)
- **レスポンス**: 204 No Content
- **エラー**: 404 Not Found、500 Internal Server Error

#### 5.2.5 ゲーム検索
- **メソッド**: GET
- **パス**: `/games/search`
- **クエリパラメータ**: `q` (検索キーワード、タイトル部分一致)
- **レスポンス**: 200 OK + ゲーム配列
- **エラー**: 500 Internal Server Error

#### 5.2.6 統計情報取得（オプション）
- **メソッド**: GET
- **パス**: `/games/statistics`
- **レスポンス**: 200 OK + 統計情報オブジェクト
  - `total_count`: 総数（int）
  - `platform_counts`: プラットフォーム別のゲーム数（map[string]int）
  - `publisher_counts`: 発売会社別のゲーム数（map[string]int）
  - `genre_counts`: ジャンル別のゲーム数（map[string]int）
  - `series_counts`: シリーズ別のゲーム数（map[string]int）
  - `year_counts`: 発売年別のゲーム数（map[int]int）
  - `total_price`: 総購入金額（int）
  - `average_price`: 平均価格（float64）
- **エラー**: 500 Internal Server Error

### 5.3 エラーレスポンス形式
- **形式**: JSON
- **構造**: 
  ```json
  {
    "error": "エラーメッセージ",
    "code": "エラーコード（オプション）"
  }
  ```

## 6. ユースケース

### 6.1 ゲーム情報の登録
1. ユーザーが新しいゲームを購入した
2. ユーザーがゲームの基本情報（タイトル、発売年、発売会社、プラットフォーム）を入力する
3. 必要に応じて任意項目（シリーズ、ジャンル、価格）を入力する
4. システムがデータを検証し、問題がなければデータベースに登録する
5. 登録されたゲーム情報がユーザーに返される

### 6.2 ゲーム情報の検索・閲覧
1. ユーザーが保有ゲームの一覧を確認したい
2. 必要に応じてフィルタリング条件（プラットフォーム、ジャンルなど）を指定する
3. システムが条件に合致するゲーム一覧を返す

### 6.3 ゲーム情報の更新
1. ユーザーが既存のゲーム情報を修正したい（例: 価格を追加、ジャンルを修正）
2. ユーザーがゲームIDと更新したい項目を指定する
3. システムがデータを検証し、問題がなければデータベースを更新する
4. 更新後のゲーム情報がユーザーに返される

### 6.4 ゲーム情報の削除
1. ユーザーが誤って登録したゲームを削除したい
2. ユーザーがゲームIDを指定して削除を実行する
3. システムが該当ゲームをデータベースから削除する
4. 削除が完了したことをユーザーに通知する

### 6.5 統計情報の確認
1. ユーザーが保有ゲームの統計を確認したい
2. ユーザーが統計情報取得APIを呼び出す
3. システムが各種統計情報を集計する
4. 集計結果がユーザーに返される（プラットフォーム別のゲーム数、総購入金額など）

## 7. 制約事項

### 7.1 技術的制約
- 技術スタック: Go 1.22+, Gin, GORM, SQLite（Fundamental-Rules 準拠）
- Windowsローカル環境でのみ動作
- 計画文書ではコードを記述しない（Fundamental-Rules 1.計画策定要件）
- テスト駆動開発（TDD）で実装を進める（Fundamental-Rules 2.2）
- テスト命名規則と配置: `_Unit`/`_Integration`, `tests/integration/` を遵守（project-coding-rules）

### 7.2 機能制約
- 認証・認可機能は実装しない
- 画像やファイルのアップロード機能は実装しない
- 外部APIとの連携は実装しない
- ページネーション機能は初期実装では実装しない（オプション）

### 7.3 データ制約
- データベースはSQLiteを使用する
- データベースファイルはローカルに配置する
- データのバックアップ機能は実装しない

## 8. 用語定義

- **ゲームソフト**: 本サービスで管理する対象となるゲームソフトウェア
- **プラットフォーム**: ゲームが動作するハードウェアまたはOS（例: PlayStation 5, Nintendo Switch, PC）
- **発売会社**: ゲームを発売・販売した会社
- **シリーズ**: 複数のゲームが属する同一のシリーズ名
- **ジャンル**: ゲームの種類やカテゴリ（例: アクション, RPG, アドベンチャー）
