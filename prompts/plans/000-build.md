# ビルドスクリプト実装計画（@prompts/ideas/000-build.md 準拠）

## ゴール
- Windows 環境で Go 1.22+ を対象に、ビルド・テスト・成果物配置を一元化するビルドスクリプトを作成し、規定の実行モード（all/unit/integration/build-only）を提供する。
- バイナリを `bin/` へ配置し、ユニットテストと結合テストの実行を分離・切替できるようにする。

## 前提・制約
- 技術スタック: Go 1.22+, Gin, GORM, SQLite（Fundamental-Rules 準拠）。
- 計画文書ではコードを記述しない（Fundamental-Rules 1.計画策定要件）。
- テスト命名規則と配置: `_Unit`/`_Integration`, `tests/integration/` を遵守（project-coding-rules）。

## 成果物
- プロジェクトルート: ビルドスクリプト 1 本（PowerShell またはバッチ）。実装時に拡張子と実行方法を明示。
- 成果物配置: `bin/` ディレクトリに実行ファイル（例: `game-list.exe`）。既存バイナリの上書き or クリーン処理をスクリプトで扱う。

## 実装方針（設計の骨子）
- エントリーポイント: 実行モード引数/環境変数を受け取り、デフォルトは `all`。
- ビルド機能: `go build` を用いて依存解決込みでコンパイル。`bin/` 不存在時は生成。
- テスト機能:
  - ユニット: `go test -run "_Unit$" ./...`
  - 結合: `go test -run "_Integration$" ./...` または `./tests/integration/...`（必要なら `-tags=integration`）
  - 全テスト: ユニット→結合の順で実行。
- エラーハンドリング: 各ステップで成否判定し、失敗時は非 0 終了コードと明示的メッセージ。
- ログ出力: 開始/終了、バイナリパス、実行モード、失敗理由を標準出力/標準エラーに記録。

## タスクと工程（論理順）
1. 仕様再確認: Fundamental-Rules / project-coding-rules / ideas ドキュメントの反映確認。
2. スクリプト雛形: 引数/環境変数の受け口、ヘルプ表示、終了コード方針を定義。
3. ビルド処理:
   - `bin/` 生成とバイナリ名決定。
   - `go build` 実行とエラー出力整備。
4. テスト実行機構:
   - ユニットテスト実行モード（`_Unit` フィルタ）。
   - 結合テスト実行モード（`_Integration` または `tests/integration/...`）。
   - 全テスト（ユニット→結合）フロー。
5. 実行モード切替:
   - `all`/`unit`/`integration`/`build-only` の分岐。
   - 不正モード時のエラー表示。
6. ログと終了コード整理:
   - 各処理の開始/完了ログ、失敗時のメッセージ。
   - 正常時 0、異常時 非 0 の終了コードを統一。
7. ドキュメント反映:
   - README などに利用方法を追記（実行例、前提ツール、モード説明）。

## テスト計画
- ビルド機能:
  - 正常: 有効な Go コードで `bin/` にバイナリが出力される。
  - 異常: コンパイルエラー時に非 0 終了＋エラーメッセージ。
- ユニットテスト機能:
  - `_Unit` のみ実行されること、成功時 0、失敗時 非 0。
  - テスト不在時の挙動確認。
- 結合テスト機能:
  - `_Integration` のみ実行されること、必要バイナリ確認後に実行。
  - 設定ファイル不足など異常時のエラーと終了コード。
- 実行モード切替:
  - `all`/`unit`/`integration`/`build-only` が指定通り動作する。
  - デフォルトが `all` であること。

## 完了条件
- ビルド、ユニット、結合テストがスクリプト経由で実行でき、`bin/` にバイナリが配置される。
- 実行モードの切替とエラーハンドリングが期待通り動作する。
- Fundamental-Rules および project-coding-rules の要件を満たす。
